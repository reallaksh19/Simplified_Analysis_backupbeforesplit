# W10.12 — Framework-Neutral QA Evidence Consumer

## Runtime boundary

W10.12 replaces the unavailable QA placeholder with a framework-neutral, read-only reviewer of evidence already present in the shipped application runtime. It does not execute repository CI, engineering benchmarks, calculations, repairs, rebuilds, exports owned by other consumers, or approvals.

```text
closed workspace-consumer-registry/v9
+ current workspace-consumer-context/v1
+ current workspace-consumer-readiness/v1 rows
→ official validator and linkage assessment
→ qa-evidence-source/v1
→ qa-review-model/v1
→ deterministic qa-evidence-export/v1
```

The core lives under `src/core/qa-evidence/**` and imports no DOM, browser, React, Zustand, mock-catalog, repository-script, Node filesystem, GitHub, or application-controller authority.

## Successor contracts

```text
workspace-consumer-registry/v9
application-view-state/v9
qa-evidence-source/v1
qa-review-model/v1
qa-evidence-export/v1
```

Registry and application-view-state factories `v1` through `v8` remain unchanged. The exact navigation order remains:

```text
HOME → WORKSPACE → LOAD_CALC → PCF → SKETCHER → THREE_D_CALC
→ PIPE_SOLVER → REPORTS → QA → SETTINGS → DEBUG
```

Only registry `v9` changes QA to `IMPLEMENTED`. It requires no dataset contract, treats every current `CONTRACT_KEYS` identity as optional evidence, permits only `REFRESH_QA_EVIDENCE` and `EXPORT_QA_EVIDENCE`, and declares `READ_ONLY_RUNTIME_EVIDENCE_ASSESSMENT_ONLY`.

## Evidence identity

Consumer membership is taken from the closed registry and ordered by `APPLICATION_NAVIGATION_ORDER_V9`. Contract membership is taken from current `CONTRACT_KEYS`. No historical row count or second consumer/contract list exists.

The QA source retains:

- closed registry schema, semantic hash, consumer count and IDs;
- an explicit valid empty context or the current context identity and availability counts;
- exactly one canonical consumer row per registry consumer;
- exactly one canonical contract row per contract slot;
- retained runtime diagnostics and limitations.

The QA review model classifies valid evidence as `VALID_EMPTY`, `VALID_PARTIAL`, or `VALID_READY`. `INVALID` is reserved for rejected source integrity and is not manufactured from an absent optional contract. A no-dataset state is valid and produces `VALID_EMPTY`.

Workspace selection, active application tab, QA row selection, filters, scrolling, browser dimensions, materialization time and export time do not participate in semantic identity. Workspace version remains visible but is excluded from QA source/review hashes so selection-only version increments do not change identity.

## Official validator reuse

Contract rows call the existing:

```text
validateConsumerContract
contractDatasetId
contractLinkError
```

No competing engineering validator is introduced. Accepted retained contracts are independently checked against their official validator, dataset identity and adjacent-contract linkage. Context diagnostics preserve the distinction among absent, invalid, dataset-rejected and stale evidence.

## Lazy ownership

```text
QaEvidenceController = sole current QA source/review owner
ApplicationShellController = sole application view-state owner
WorkspaceState = sole active dataset authority
SettingsAuthority = sole settings authority
EventBus = request/outcome boundary
```

QA is not materialized during bootstrap. Opening QA or explicitly requesting refresh materializes current injected runtime evidence. Context changes refresh QA only while the page is active. A failed refresh retains the last valid source/review model and publishes `qaEvidence:refreshFailed`. Teardown removes all QA event and DOM listeners. No timer or polling loop is used.

Public read-only APIs are limited to:

```text
getQaEvidenceSource()
getQaReviewModel()
```

They return `null` before first materialization. There is no public setter or controller exposure.

## Read-only view and exports

The view uses ordinary DOM construction and `textContent`. Controls are limited to:

```text
Refresh Evidence
Export JSON
Export CSV
```

The JSON artifact contains the validated source and review model. CSV contains canonical `CONSUMERS`, `CONTRACTS`, `DIAGNOSTICS`, and `LIMITATIONS` groups with stable columns and escaping. Both are newline terminated, deterministic, timestamp-free, and immutable. Download object URLs are revoked immediately.

Opening, refreshing or exporting QA does not create or replace a dataset, change Workspace selection, alter Settings, mutate PCF or Sketcher state, run a solver, rebuild evidence, create a calculation package, create a report, or initiate an engineering export.

## Limitations

The QA consumer assesses only evidence currently injected by the application runtime. It does not prove engineering correctness beyond official contract validation already available, does not certify code compliance, does not inspect GitHub Actions or package scripts, and does not execute benchmarks, tests, calculations, solvers, rebuilds, repairs, workflow approvals, LFEA, or LAFEA application integration.

Debug remains unavailable. Legacy retirement remains W10.14 scope.

## Certification boundary

The blocking mission workflow is `W10.12 QA Evidence Consumer Certification`. It runs the W10.12 contract, property, source and browser checks, followed by `check:full` and the production build. Historical aggregate workflows and predecessor path/version assertions remain advisory and are not altered by this mission.
